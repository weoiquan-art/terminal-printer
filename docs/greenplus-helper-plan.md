## 2. 不能越过的边界（来自 ASDIC 硬约束）

1. **Green 是库存和正式单据的唯一权威。** 本程式不扣库存，不开正式单据，不维护第二套库存数字。
2. **不连接、不修改 Green 的营业数据库**（`Z:` = `\\truckmage-svr\Fameplus-ASDIC`，SQL Server），不读 `ServerConn.INI`，不绕过 Green 的 lock。
3. 数据只来自 **Green 的完整备份 `.Bak`**，用 asdic `backup` 分支的 `tools/read-backup.ps1` 恢复成本机独立的只读快照（LocalDB 实例 `AsdicBackupReader`），再导出需要的列。
4. 成本、成本暗号（`UCost String` 等）、顾客资料、金额：不进公开仓库，不印到标签，不给未登录的人看。
5. 所以本程式的数量都是「备份当时的快照」，每个画面都要显示快照日期，不能说成实时库存。

## 4. 四个画面

### 4.1 进货 → 打标签（第一优先）

- **来源 A：选收货单。** 列出快照里的收货单（单号、日期、供应商、几种货），选一张 → 明细带出货号和**收货数量 = 张数**。
- **来源 B：手动或扫码录入。** 直接输入或扫描货号，输入数量。快照里还没有的新到货（备份之后才进的）走这条。
- DESC/MODEL 由货号带出（拆分规则与 batch.py 相同），可以改；**价格每次手填**（用户已定）。快照里的售价只作为灰色提示，不自动填。
- 下一步就是现在的 batch 流程：检查整批 → 总览图 → 打印。不用再经过 Excel。
- 每次打印记一条打印记录（谁、什么时候、哪些货号、几张），可以补印。

### 4.2 查货

- 按货号（忽略空格）、名称、车型、OEM/互换号搜索。
- 显示：名称、BIN 位、快照数量与快照日期、最后进货日期/数量、互换号。**不显示成本。**
- 从结果可以直接「打一张标签」或「加入准备单」。

### 4.3 开单（只准备）

- 柜台把顾客要的货加进准备单：货号、数量、备注；可打印拣货单（按 BIN 排序）。
- 结束时导出/打印成清单，由人在 Green 里正式开单。本程式**不扣库存、不算正式金额、不生成发票号**。
- 顾客名字、电话等只在登录后可见。

### 4.4 库存报表

- 导入新快照时生成：新增货号、消失货号、数量变化最大的、零库存、低于 Min Level 的。
- 每份报表标明前后两个快照的日期。

## 5. 多人共用

- 服务仍跑在接打印机的那台电脑上；默认只给本机用，管理员在设置里打开后才允许局域网访问（店里其他电脑或手机用浏览器连接）。
- 登录：每人一个账号。角色先分两种：
  - **店员**：查货、准备单、打标签。
  - **管理**：导入快照、管理用户、看打印记录。
- 只有服务所在的电脑能直接控制打印机；别的电脑点「打印」时，任务由这台电脑发送。
- 局域网开放后要做：密码散列存储、会话超时、POST 防跨站（现有的 Origin 检查扩展成 token）、操作日志。

## 6. 技术取向

- 延续现在的做法：Python 标准库 HTTP 服务 + 纯 HTML/JS，**不引入大型框架**（CLAUDE.md 规定）。
- 自己的数据用 SQLite（标准库自带），不碰 Green 的 SQL Server。
- 打印、排版、预览全部复用 `labelkit`，与 label.py / batch.py / editor.py 同一套代码。
- 导出脚本读的是本机只读快照（LocalDB），只取白名单里的列。
